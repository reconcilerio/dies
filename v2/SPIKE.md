# dies v2 spike: core die model

This module is a spike of the core die model for the next generation of dies. It is not the v2 API. The goal is to test design decisions in code, and then generate them from upstream source.

- `die/` is the runtime: the base plus intent overlay, typed fields, collection dies and patch encoding.
- `spike/{metav1,corev1,appsv1}` hold subsets of upstream types with hand-written dies that stand in for generated ones. The `die` struct tags stand in for the `+listType`, `+listMapKey`, union and subresource markers.
- `diegen/` is a spike of the generator, in the same module as the runtime so the two are always the same version. `apis/{meta,core,apps}/v1` is its output for the upstream packages, and `examples/widget/v1` for a type declared locally. Regenerate with `go generate ./...` from this directory.

Run with `go test work`.

| Presence is kept beside the base                       | A die keeps a presence tree with its base (`die/codec.go`). Decoding records each value present on the wire, zero or not (null is absent), and the fields the Go type doesn't have, at every level: struct fields, list-map elements by key (defaulted keys included), map entries, and elements of atomic lists by index. A value fed or set from Go has no tree and follows the Go rule: nil pointers, slices, maps and interfaces are absent, as are `omitempty`/`omitzero` fields with empty or zero values, structs included. One encoder reads base, intent and presence together, and backs `MarshalJSON`, the values an apply sends whole and both sides of a merge patch's diffs; `Has` reads the same presence. `DieTare` and scopes, such as `die.Only`, fold intent into presence: what was set is present by the Go rule below it, what was cleared is gone. So `paused: false` from the server `Has`, an update sends back fields of a newer API (tested through the fake client), replacing a struct from Go sends nulls for its unknown fields in a merge patch, and encoded dies carry none of the `null`s and `{}`s the Go types add (`creationTimestamp`, `status: {}`, `containers: null`); upstream round-trip tests now compare decoded objects. Decoding parses the JSON twice, once into the Go type and once generically for presence; a single `encoding/json/jsontext` pass (in the standard library as of Go 1.27) is the efficient form. | Validation and defaulting                              | A die validates or defaults only its own fields: an immutable die that is a `die.Validator` (`DieValidate(ctx, op die.Operation) (field.ErrorList, error)`, the error for a value it can't validate, which stops validation, located), or a mutable die that is a `die.Defaulter` (`DieDefault(ctx) error`), usually by a hand-written method on a generated die. `die.ValidateCreate(ctx, d)`, `die.ValidateUpdate(ctx, d, old)`, `die.ValidateDelete(ctx, d)` and `die.Default(ctx, m)` walk the die's struct fields (held by value, or by pointer when present) and list-map elements, finding each child die through the field tables, so the dies between need no plumbing: `examples/widget/v1`'s ports are defaulted and validated through a `Widget` and its spec, which have no methods. Defaulting is top down, each die walked after its parent's defaults, and stops at the first error, located. Validation returns apimachinery's `field.ErrorList`, located from the root, with the schema's errors captured automatically, made with apimachinery's declarative validation (`k8s.io/apimachinery/pkg/api/validate`) so they are the server's: required fields (`+required` and kubebuilder's need the key present; `+k8s:required` also not empty unless a pointer; an undefaulted list-map key is not empty), unions (`+oneOf` and `+k8s:unionMember` exactly one, `+zeroOrOneOf` and `+die:union` at most one), and value checks of declarative validation's markers (`+k8s:format`, `+k8s:minimum`/`maximum`, `+k8s:maxLength`/`maxBytes`/`maxItems`, `+k8s:unique=set`, `+k8s:eachVal`), kubebuilder's (`Minimum`, `Maximum`, `ExclusiveMinimum`/`Maximum`, `MultipleOf`, `MinLength`/`MaxLength`, `Pattern`, `Enum`, `Format`, OpenAPI's formats through kube-openapi, `MinItems`/`MaxItems`, `UniqueItems`, `MinProperties`/`MaxProperties`, `items:…`), `+enum` (the constants of the field's type, or of a list's item type) and `+listType=set`. A marker on a type holds for its fields. diegen writes them as die tag options (`required`, `required=nonzero`, `oneOf=…`, `enum=[…]`, `pattern="…"`, `each.…`), which the runtime parses into each field's checks; an atomic list of items with dies records them (`fields.NewItems`), so its items are walked by index. A package with kubebuilder's markers of custom resources (`+kubebuilder:object:root`, `resource`, `subresource`, `printcolumn`, `storageversion`, `skipversion`, or a package-level `+kubebuilder:validation:Optional`/`Required`) has kubebuilder's convention that a field without omitempty or omitzero is required unless `+optional`; markers that only validate, as metav1.Condition's do for the custom resources that use it, don't make `meta/v1` or `core/v1` such a package. `Default` sets each absent field with a `+default` or `+kubebuilder:default` before calling the die's `DieDefault`. `die/validation` makes field errors at a die or handle (`Required`, `Invalid`, `NotSupported`, `TooMany`, …, reading the value there), and `validation.Path` converts a location to a `field.Path`, a list-map element as its index, as the API server reports it, or its keys when the list doesn't have it. The operation tells a `Validator` what is validated, `die.Create`, `die.Update` or `die.Delete`, as an admission webhook's request does; `die` has its own operation type, as apimachinery's has no delete. For an update, such as in a webhook or before sending it, each die is paired with the old die at its location (a field by name, a list-map element by key, an atomic list's item by index), which `die.OldOf(d, op)` returns as the die's type. ### Generator findings

- **Upstream states many markers twice,** as `+listMapKey=name` and `+k8s:listMapKey=name`. Naive normalization produced a duplicate key, so values are deduplicated.
- **`VolumeSource` and `ProbeHandler` have no union markers,** only `+optional` on each member and a sentence in the docs. Union clearing needs another source, such as a marker overlay the generator reads.
- **An embedded type with a json name** (`ObjectMeta` at `metadata`) gets an accessor named after its wire name: `Metadata()`, not `ObjectMeta()`.
- **Some `+default` values are not JSON** (`ref(...)` to constants). They are skipped for now.
- **Some `+default` values are JSON objects** (`{"single": {}}` in `scheduling/v1alpha3`), which the `{…}` list syntax misread. Defaults are now always taken whole, and an invalid default fails generation instead of panicking at init.
- **Upstream methods come with the types,** now that they are referenced. Owned types with custom JSON methods are rejected, as their encoding can't be generated.
- **A collection die has no whole-value getter.** Reaching `ResourceList.Cpu()` means releasing the parent: `Resources().DieRelease().Limits.Cpu()`. Collections could offer `Get()`, but it would return the named map type only if the die knows it.
- **`+default` appears on many non-key fields** (`AzureDiskVolumeSource.FSType` defaults to `ext4`). The runtime only uses defaults to normalize keys, so these are recorded but have no effect yet.
- **Multi-key structs are generated in the package that has the list**, named after the element (`ContainerPortKey`). A list in another package with the same element gets its own key type.
- **apimachinery types with `TypeMeta`** (`Status`, `ListOptions`, …) are not marked as objects: they are shared by every group, so they have no `apiVersion` of their own.
- **The pinned `golang.org/x/tools` cannot read Go 1.27 export data,** so every load type checks from source. That is also what makes upstream docs available.

## Decisions the spike changed

1. **Scopes fold rather than reset.** Discarding the intent outside the kept paths lost the object's identity: the status apply had no name, because the name was only intent. The dropped intent is now folded into the base. The value stays complete, and only the kept intent is sent.
2. **Leaf fields are handles, like collections.** This replaces separate `X()`/`SetX()`/`HasX()`/`ClearX()` methods. Each field gets one method, which removes the naming collisions found in `k8s.io/api` (`SetHostnameAsFQDN`, `Capabilities.Add`, `PodIP` and `PodIPs`). Upstream pointer scalars (`*int32`) use `Optional`, which reads and writes the value and reports presence separately. Framework methods on child dies keep the `Die` prefix (`DieHas`, `DieClear`), because their other methods are field accessors. Handles have no fields, so their methods don't need it. The cost is longer reads: `.Get()` everywhere.
3. **Immutable and mutable dies are separate types.** One type that was either made writes on an immutable die compile, and fail at run time: a write through a child had nowhere to go and panicked, while one on a root returned a new root, so the same call meant two things. Now an immutable die has no methods that write, and the mutable die's write in place. Methods Go needs on both, such as `metav1.Object`'s setters, panic on the immutable die. Data conflict checks, such as duplicate list-map keys, are still open.

## Gaps found

- ~~**`Has` on fed or decoded values** falls back to "not zero".~~ Fixed by the codec: see "Presence is kept beside the base".
- ~~**A value set whole** is encoded with `encoding/json`.~~ Fixed by the codec. It was worse than noted: setting a pod template whole sent `"containers": null` in an apply, which would clear another owner's containers.
- ~~**Ergonomics of the immutable-child rule:**~~ Gone with the split: an immutable die has no writes to misuse. The cost is spelling the mutable type in `DieStamp` functions (`func(d *DeploymentDieMut)`), feeding blanks included.
- **Pointer identity:** a leaf's write returns the die it is a field of, the same pointer. A die's own writes, such as `DieFeed`, still return a new wrapper around the same state.
- **The `DieFrom` hooks are exported** on every die, immutable and mutable, as expected.
- **The embedded state type is `base.DieBase`,** so every die has a field named `DieBase`. A field accessor named `DieBase()` would not compile ("field and method with the same name"), so it is one of the reserved `Die*` names. A field named `Base`, which a CRD could plausibly have, is now fine.
- **Changing a field between unset and its default** (`protocol: ""` to `"TCP"`) is recorded as a real change, even though it changes nothing once the server applies defaults. Should intent treat unset and default as equal for every field with a `+default`, or only for keys?
- **Upstream: unstructured implementations other than apimachinery's.** controller-runtime's informer cache holds `*unstructured.Unstructured` for every `runtime.Unstructured` kind and only hands out objects of an assignable Go type, and its fake client checks the concrete unstructured types, so an `unstructured.Object` can't come from the cache. apimachinery's `meta.SetList` and `ExtractList` find a list's items by reflecting on an `Items` field (a TODO there says an interface will replace it), which is why list dies are plain lists. Both need filling upstream. Until then, read the cache as unstructured objects and feed them, or go through reconciler.io/runtime's duck wrapper, which converts typed dies the scheme doesn't know (an `IsDuck` that also took other `runtime.Unstructured` implementations would cover unstructured dies).
- **A die read back after a write shows its intent on top** of what the server returned, as decoding keeps intent. After an apply the server didn't fully honor, such as one that left out another manager's field, the die shows the intent, not the server's state. Pass a die without intent (read, or tared) to see exactly what the server has.
- **Real clients send built-in types as protobuf.** controller-runtime's client asks for protobuf for any kind client-go's scheme has, unless the rest config sets a content type, and dies are JSON, so a client for dies needs `ContentType: runtime.ContentTypeJSON`. reconciler.io/runtime would need to set it, or dies to say they're JSON only.
- **Not yet supported:** accessing an inlined struct as a whole (`vol.VolumeSource()`, an empty path step), strategic merge patch, and ordering of new list-map elements beyond appending.
